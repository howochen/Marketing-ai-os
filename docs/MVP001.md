## 可用功能與本次差異

- 沿用 `/app/automation`、OAuth／Vault／Token refresh、Task／Revision／A21／Ledger、既有 Worker及官方兩階段 Publisher。
- 設定一次品牌、方向、帳號、每日上限／時段、模型、加密 Key、月預算、期限。既有一鍵暫停及一般登出不影響有效政策。
- 品牌自主創作模式不因方向用完就永久停止：可再使用 Owner 允許的方向，載入最近3篇同 Tenant 文案作為不可信參考；原有相似度、事實／禁用詞／空白／長度檢查保留。最多一次品質重寫，不重送未知結果。
- 修復並行 Worker 讀取舊 slot 的競態：取得 Tenant lock 後重新讀取 slot，避免同一篇建立兩份 Publication。
- 用既有不可變政策 JSON 與 Audit 保存 D 授權，不新增資料表、Migration、預算系統、OAuth或常駐服務。
- 真實 Provider／發布的舊無條件開發鎖，僅對通過 B／C／D 的指定政策改為條件准入。舊 synthetic Batch／其他 Live paths 仍鎖定。
- 真實 Provider 逐次檢查：政策與原 Owner 安全撤權、期限、Tenant Kill Switch、既有 Ledger預留、Task RUNNING／expiry、狹義 Worker與policy scope、prompt hash、固定 payload／模型／output1024。一次計數及一次生成，無tools、fallback或網路重試。
- 每個 Writer／語意審查仍使用原 Ledger。超額完整記帳並停止；未知結果保存安全分類與 Provider IDs，slot／待對帳許可阻止後續花費。usage 不等於驗真帳單。
- Worker 現有 `restart: unless-stopped` 保留。使用者已另准**只修改程式設定**：四個 Worker開關可配置但全部預設false；沒有套用至任何運行中的容器或環境。

## Windows 最少操作

1. 保持 Windows 開機、網路正常；Docker Desktop可選登入Windows時啟動。電腦睡眠／關機時不能發文，恢復後不補發過期內容。
2. **尚未部署此版本。** 先另外批准把此版本部署到受控環境及既有必要 schema0013～0015的升級；本次沒有新增 Migration，也沒有升級原DB。由 Codex啟動API及既有automation服務，使用者不需手改環境變數。
3. 進既有 `/app/automation` 選現有Threads帳號、品牌方向、每日篇數／時段、模型及Key、月預算與期限。新政策先保持離線／待授權，Key不貼聊天。
4. 依序完成 B、C。兩者成功後才選真實執行、B紀錄及該帳號C紀錄；Owner檢查 D確認文字後啟用。原服務預設不啟動automation profile；後端開關須等D批准後才由Codex設定並啟動。
5. 之後不需每天開網頁或逐篇批准；到期、撤銷、預算不足、無效Token、QA失敗或未知結果會停下。可用「暫停全部自動化」立即阻止新工作。

若既有品牌與工作台資料在原DB，不會自動搬進隔離環境；未獲批准不複製正式憑證、資料或Volume。不需要重新設定OAuth、Meta App或DPAPI。
