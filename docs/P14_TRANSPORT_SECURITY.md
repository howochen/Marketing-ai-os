# Transport security

`app/live_transport.py` contains fixed HTTPS Responses HTTPX wiring: POST only, exact api.openai.com path, key read from environment only at send, test environment only, no redirects/proxy trust/retry, existing 20s total phase timeout/connect5 supplied by parser Client. The underlying transport has retries0; buffered response is read before closing transport. No key/database/log persistence. Request/response errors use fixed categories with suppressed raw exceptions.

Every entry (`ControlledOpenAIProvider.generate/check_offline`, `LockedHTTPTransport.handle_request/_send_once`, durable prepare) is blocked by release code or stricter authorization validation. `require_execution_release()` always raises LIVE_EXECUTION_NOT_AUTHORIZED. Env true/key/forged approval cannot bypass it, including the private wiring method. Default OpenAIProvider still accepts exact MockTransport only; widening its type annotation does not change runtime checks. CI/normal pytest/Docker startup never instantiate enabled Live wiring. No route accepts transport, key or executable grant.

The internal durable preparation reuses lock_tenant, assigned worker checks, batch/attempt tenant lookup, durable reservation/dispatch identity, operator validity, caps/rate pins and kill/unknown state. Synthetic batch status and INTERNAL_APPROVAL_ONLY fail closed. It is intentionally not called by the synthetic executor or exposed through HTTP. Future enabling requires a separately reviewed durable executor integration, not deletion of one lock or a flag change.

Shared parser rejects unsupported models, unknown/inconsistent usage fields, malformed totals and control characters in IDs; schema/refusal/incomplete outputs do not approve content. Dormant real receipt mapping distinguishes provider-estimated/unverified billing from synthetic fees; incomplete/unpriced/over-limit output requests reconciliation. Future real settlement must preserve raw evidence and route into the same ledger/recovery, never SETTLE_MOCK or INVOICE_VERIFIED. Existing database deliberately cannot store a paid attempt in synthetic history.

Tests: tests/test_live_readiness.py plus existing test_durable_gate.py, provider/readiness/revision suites. Multi-worker last-slot, eight contenders, process restart, post-dispatch crash/timeout, overrun, immutable approval/revision and manual publication retain existing regression coverage. Offline tests that bypass the lock assert exact MockTransport and remove provider environment keys; no external request occurs.

Residual risk: Python code changes/admin-host compromise can bypass application policy; these are not security proofs against a malicious deployment operator. External delivery is not exactly once, and local caps cannot guarantee a delayed external invoice never exceeds an estimate. No production penetration test or real account validation was performed.
